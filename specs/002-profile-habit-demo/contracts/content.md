# Runtime content interface

Extends the existing public JSON editor contract, [spec.md](../spec.md) FR-001/004/005/009–012 and baseline src/content/types.ts, validate.ts and load.ts. No new endpoint or dependency.

## Loading and identity

Keep `schemaVersion: 1` and `/config/app-content.json`, fetched no-store with full validation before dependent screens mount. Preserve built-in Spanish loading/error/retry strings when no config is readable. Text is rendered as text, never HTML. IDs follow the existing stable `[a-z][a-z0-9-]*` grammar, unique within collection, never labels or array indices. Unknown/duplicate scenario/chat/answer/image/destination IDs, wrong-sport or unsafe references fail the document. Error feedback identifies the offending path in Spanish. Retry refetches; no bundled plausible product fallback.

## Bundled-local photo boundary

Use an `images` collection and `imageId` references for new photo assignments. Each photo record has stable ID, explicit root-absolute allowed local path, Spanish alt, subject kind/id (exercise or general sport), source URL/attribution/provenance, license verification status and evidence reference. An exercise assignment must name that exact exercise subject; general sport art is not exercise correspondence evidence. Preserve existing three SVGs as explicitly general/environment illustration only.

Authority is NOT established by JSON declaring itself approved. A developer-controlled exact allowed-path/subject registry, updated only alongside separately approved verified local assets, bounds runtime display. Accept only literal canonical paths in that registry and a verified provenance entry; reject http/https, `//`, data/javascript, backslashes, query/fragment tricks, percent-encoded traversal, `..` or unapproved paths. Source/provenance URLs are metadata, never runtime image fallback requests. Missing/unverified photo assignment is explicit unavailable status with Spanish feedback and preserved exercise text; unsafe claimed paths and dangling image IDs fail validation. A bundled file load failure also renders unavailable-image feedback, never a remote fallback.

No assets are approved by this document. Supplied Pexels evidence includes license GET 403 and no verified bundled photos; manifest/CSV titles prove neither rights nor matching subject. Before registering/displaying a photo, later separately authorized work must verify permission/license, actual local bytes and visual correspondence. Safe unavailable feedback does NOT satisfy SC-003 matching-image acceptance. No download or redistribution authority, remote loader, new dependency or rights claim is introduced.
