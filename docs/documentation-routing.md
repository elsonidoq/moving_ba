# Documentation routing

## Authoritative owners

These categories are supported by the existing conceptual HTML artifact and the
approved Coherence documentation/memory association. Owners describe current state;
secondary references must point to them rather than duplicate their contents.

| Material change | Authoritative owner | Repository evidence |
| --- | --- | --- |
| Demo structure, inline rendering/state, sport/profile selection, individual/class flows, continuity or reward simulations | [Architecture](architecture.md); the [HTML mockup](mockup_ba_en_movimiento_v2.html) remains the artifact | Inline script, `state`, `render`, screen functions and visible disclaimers |
| Documentation file ownership, new direct documentation files or child directories | [Documentation index](README.md), with `README.md` in each child documentation directory | Approved documentation-root/index convention in [AGENTS.md](../AGENTS.md) |
| Coherence runtime, package-contract association, memory path or retrieval/write policy | [Project instructions](../AGENTS.md) and the associated [memory index](../memory/MEMORY.md) | Marked Coherence contract and project-local index |
| Verified unresolved defect, risk, shortcut or actionable investigation | [Canonical open issues](open_issues.md), through installed `track-open-issue` | Approved canonical register; do not invent findings from conceptual data |

## Scope limits and newly evidenced categories

Deployment ownership is [deployment.md](deployment.md), but no deployment-relevant
system or action is currently verified. Route concrete operational evidence there
when introduced, retaining unknown fields instead of invented procedures.

No backend/API, authentication, database, or test-system category is claimed to apply
on current evidence. If such material appears, verify it and obtain any missing
ownership choice before extending this guide. A persistent database requires an
explicit authoritative schema owner/documented set covering collections/tables,
fields/types, keys/relationships, constraints, and indexes as applicable.

Non-obvious verified trigger-first gotchas belong in associated project memory under
installed `memory-handling`, not a duplicated current-state description. Explicit
future-directed coordination feedback follows its separate installed contract;
ordinary documentation work does not authorize guideline storage.
